# Wovyr documentation website

An [Astro Starlight](https://starlight.astro.build) site rendering the canonical
`../docs` tree. **`../docs` stays the source of truth** — nothing in
`src/content/docs/` is hand-edited; it is regenerated by `scripts/sync-docs.mjs`
(and gitignored).

```bash
npm ci
npm run dev     # sync docs + local dev server
npm run build   # sync docs + static build to dist/
```

## What the sync script does (`scripts/sync-docs.mjs`)

- Adds the frontmatter Starlight requires: a `title` (the doc's opening H1 when
  it has one, else a humanized filename) and an explicit `slug`.
- Injects a **"Status: Planned"** caution on every page whose own `**Status:**`
  header marks it planned / exploratory / aspirational / target-state /
  not-implemented. Plain "Draft"/"Active"/"Done" statuses (doc maturity, not
  feature status) get no banner. Misclassifications are overridable via the
  `FORCE_PLANNED` / `FORCE_SHIPPED` sets in the script.
- Rewrites relative `.md` cross-links to site routes; links leaving `docs/`
  (crate paths, `openapi.yaml`, SDK dirs, …) become GitHub blob URLs.
- Resolves the `v1.0.md`-next-to-`v1.0/index.md` route collisions by moving the
  directory index to `<dir>/overview`.
- Skips `docs/SUMMARY.md` (the sidebar replaces it) and generates the landing
  page (`index.mdx`) itself.

The sidebar is defined in `astro.config.mjs`, one collapsed group per numbered
`docs/` section.
