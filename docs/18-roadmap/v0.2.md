# Roadmap: v0.2 — Memory, Tools & Gateway Hardened

**Document ID:** RM-002  
**File Path:** `docs/18-roadmap/v0.2.md`  
**Version:** 1.1.0  
**Status:** In progress (workflow engine core implemented)  
**Owner:** Product Team  
**Last Updated:** 2026-06-27

---

# 1. Theme

**Depth and durability.** Make the core engines production-shaped: real memory,
durable workflows, stronger tool isolation, and a resilient gateway.

---

# 2. Goals

- **Memory Engine**: PostgreSQL + Qdrant tiers, hybrid
  [retrieval](../06-memory-engine/retrieval.md), ranking, compression.
- **Workflow Engine**: durable executions with
  [checkpointing](../03-workflow-engine/checkpointing-specification.md),
  [retry](../03-workflow-engine/retry-engine.md), and
  [compensation](../03-workflow-engine/compensation-engine.md).
- **Tool Runtime**: container + gVisor/microVM sandboxes
  ([sandbox runtime](../07-tool-runtime/sandbox-runtime.md)) and worker pools.
- **LLM Gateway**: failover, circuit breaking, caching, token/cost accounting.
- **Observability**: metrics, tracing, logging baseline
  ([section 14](../14-observability/index.md)). **Done** (core: Prometheus metrics +
  structured logging).

---

# 3. In Scope

| Area | Deliverable | Status |
|------|-------------|--------|
| Memory | Namespaces, hybrid search, knowledge graph (v1) | **Done** (core); KG/Qdrant pending |
| Workflow | DAG + state machine + durable resume + compensation + branching + human approval | **Done** (core); timer/event waits + distributed/Postgres pending |
| Tools | Strong sandboxes, fair scheduling, autoscaling | Native/Container/gVisor/WASI backends + enforcement done; microVM gated; pooling/autoscaling pending |
| Gateway | Resilience + caching + cost events | **Done** (core) |
| Ops | Dashboards, alerts, SLOs | Planned |

> **Workflow engine core (done):** `crates/apex-workflow` — DSL + validation,
> event-sourced state machine, deterministic DAG scheduler, **conditional branching**
> (guarded transitions + branch skipping), per-activity retry, **saga compensation**
> (reverse-order rollback), and **durable suspend/resume** (the `Interrupted` waiting
> state — e.g. human approval). CLI: `apex workflows validate|run|approve`. Remaining:
> timer/event waiting states, parallel/distributed workers, Postgres persistence.
>
> **Memory engine core (done):** `crates/apex-memory` — namespaces, hybrid retrieval
> (vector + keyword via RRF), weighted ranking (relevance + recency + importance)
> with score breakdown, in-memory + file stores; embeds via the LLM Gateway. CLI:
> `apex memory put|query`. Remaining: Postgres/Qdrant backends, knowledge graph, MMR
> diversification, compression, ABAC filtering.
>
> **Gateway resilience (done):** `crates/apex-provider` — the `Gateway` now holds an
> ordered candidate list with per-provider circuit breakers, retry of transient
> errors with exponential backoff, failover, an exact response cache, and cost
> events. Remaining: Redis-shared breaker state, semantic caching, hedging.
>
> **Observability baseline (done):** `crates/apex-telemetry` — a Prometheus `Metrics`
> registry (counters + histograms) and structured (JSON) logging. The server exposes
> `GET /metrics` with RED route metrics and `apex_llm_*` cost/token metrics fed by
> gateway cost events. Remaining: OTLP trace export, exemplars.
>
> **Tool sandbox backends (done):** `crates/apex-tools` — the `SandboxBackend`
> spectrum, `TrustClass` isolation floors, and `select_backend`/`SandboxManager`
> (strongest of preference/floor/trust, then capability check; `SandboxManager::detect`
> probes the host). Backends: `NativeSandbox` enforces memory/CPU caps via `setrlimit`
> plus timeout + output cap; `ContainerSandbox` runs Docker/Podman with cgroup
> memory/CPU/PID limits, a read-only rootfs, a bind-mounted workspace, and
> `NetworkPolicy` egress control (`--network none` on deny), and drives **gVisor** via
> `--runtime=runsc`; `FirecrackerSandbox` builds a microVM config and is
> capability-gated. A `WasiSandbox` (behind the `wasi` cargo feature) runs
> `wasm32-wasi` modules in an in-process Wasmtime VM with capability-based isolation
> and memory/fuel/epoch limits. Container/gVisor execution is covered by
> capability-gated integration tests; WASI by in-process tests. Remaining: an egress
> proxy for per-host allow-listing, a Firecracker guest agent for in-VM execution,
> and warm pooling.
>
> **Remaining v0.2 areas:** sandbox warm pooling/autoscaling; ops
> dashboards/alerts/SLOs (largely belong with the v0.3 dashboard).

# 5. Exit Criteria
