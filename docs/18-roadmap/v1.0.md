# Roadmap: v1.0 — General Availability

**Document ID:** RM-004  
**File Path:** `docs/18-roadmap/v1.0.md`  
**Version:** 1.5.0  
**Status:** In progress — two workstreams now have code. DX/SDK has three slices: a
hand-authored OpenAPI 3.0 spec (`docs/09-api/openapi.yaml`, cataloging every
route `apex-server` actually implements), a TypeScript client (`sdks/typescript`,
with `GET`-only retry/backoff, a `paginateAll()` iteration helper, and an
`npm test`-wired `redocly lint` contract check on the spec — built and
verified importable from a real package tarball, but **not yet published to
npm**: publishing requires a live 2FA OTP, deferred), and a **Python client**
(`sdks/python`, stdlib-only — no `requests`/`httpx` dependency — mirroring the
TypeScript client's resource shape 1:1, with the same retry/backoff and
pagination helpers, integration-tested against a live server with `unittest`)
— **published to PyPI as [`apex-ai-sdk`](https://pypi.org/project/apex-ai-sdk/)
and verified installable** (`pip install apex-ai-sdk` into a clean venv,
imports correctly), plus a [deprecation-window policy](../09-api/deprecation-policy.md)
(90-day minimum, `Deprecation`/`Sunset` headers, `/v2` parallel-run rule) — all
integration-tested against a live `apex dev` server. **Security's key-management
row also has a first slice**: `apex-kms`, a new crate implementing
[Encryption §5](../13-security/encryption.md#5-key-management)'s hierarchy
(root key wraps versioned tenant keys, tenant keys wrap per-use DEKs) — the
`Kms` trait plus a `LocalKms` implementation (AES-256-GCM via `ring`,
already in the dep graph), covering rotation (`rotate_tenant_key` +
`rewrap_data_key`, without re-encrypting the data a DEK protects) and
crypto-shredding (`destroy_tenant_key`, fail-closed thereafter). 22 unit
tests, clean `clippy`/`fmt`. Not yet done: a cloud-KMS-/HSM-backed root,
wiring into a real consumer, server/CLI surface, audit integration — this is
the primitive, not yet plumbed through. Everything else in this roadmap
(HA/DR, sharding, compliance mapping, multi-region) remains unstarted — see
§3 below, which is still directional rather than a checklist with exit
criteria the way v0.1–v0.3 had.  
**Owner:** Product Team  
**Last Updated:** 2026-07-04

---

# 1. Theme

**Production-ready GA.** Stability, scale, security, and operability sufficient for
enterprises to run critical workloads.

---

# 2. Goals

- **Stability**: stable APIs, DSL, plugin API; documented compatibility guarantees.
- **Scale**: validated at target NFRs — billions of memories, thousands of
  concurrent runs ([performance](../15-testing/performance-tests.md)).
- **Security & compliance**: hardened posture, audit, supply chain; readiness for
  SOC 2 / ISO 27001 / GDPR ([security](../13-security/index.md)).
- **Operability**: HA deployment, autoscaling, runbooks, SLOs
  ([deployment](../12-deployment/index.md), [observability](../14-observability/index.md)).
- **Multi-region** option for residency and resilience.
- **SDKs** beyond Rust (e.g. Python/TypeScript client SDKs).

---

# 3. In Scope

| Area | Deliverable | Status |
|------|-------------|--------|
| Reliability | HA, DR, backup/restore, chaos-validated | Not started — `docs/12-deployment/{kubernetes,helm,terraform}.md` are spec-only, no artifacts exist in the repo |
| Security | Pen-tested, compliance-ready, key management | **In progress** — audit/secrets/RBAC groundwork exists (`apex-audit`/`apex-secrets`/`apex-tenancy`, all v0.3), and the envelope-encryption KMS hierarchy in `docs/13-security/encryption.md` §5 now has a first code slice: `apex-kms` (`Kms` trait, `LocalKms`, rotation, crypto-shredding — see DX-adjacent detail in the status note above). Remaining: a cloud-KMS-/HSM-backed root, wiring into a real consumer (memory/secrets), server/CLI surface, audit integration, pen-testing, and compliance mapping (SOC2/ISO27001/GDPR — a policy/process effort, not something built) |
| Scale | Sharding/partitioning, multi-region option | Not started at real scale — `apex-memory`/`apex-provider` perf tests are deliberately toy-scale (250 records, in-process mock provider); billions-of-memories / thousands-of-concurrent-runs needs real capacity engineering against live Postgres/Qdrant |
| Ecosystem | Mature marketplace, monetization (v1) | Not started (marketplace core itself is done in v0.3; monetization/abuse-report remain open per that roadmap) |
| DX | Stable SDKs, polished docs, migration guides | **In progress** — `docs/09-api/openapi.yaml` (hand-authored spec covering every implemented route) + a TypeScript client (`sdks/typescript`) with retry/backoff and pagination helpers, a `redocly lint` contract test wired into `npm test`, **+ a Python client (`sdks/python`, stdlib-only, same resource shape + retry/pagination helpers, `unittest`-tested against a live server) — published to PyPI as `apex-ai-sdk`**, and a [deprecation-window policy](../09-api/deprecation-policy.md), all integration-tested against a live server. Remaining: **npm publish of `sdks/typescript`** (blocked on a live 2FA OTP the operator needs to supply interactively — deferred, not a code gap), further language clients, polished docs/migration guides |

---

# 4. Compatibility Commitments

- `/v1` API and plugin API: backward-compatible within the major version.
- Deprecations announced with a window; breaking changes only at major bumps
  ([API versioning](../09-api/overview.md#3-base-url--versioning)).

---

# 5. Exit Criteria

- Meets published SLOs ([alerting](../14-observability/alerting.md)) in production.
- Passes security review and external pen test.
- Reference customers running critical workloads.
